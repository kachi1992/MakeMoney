# 13 · 模拟盘与执行引擎

关联 FR-010/011/012。目标是可复现地测试建议，不是假装能够无摩擦地实盘成交。Alpaca 官方列出了其模拟盘不覆盖市场冲击、队列、部分费用和股息等限制，因此本项目即使后续接入外部 Paper API，也保留独立账本和执行假设；外部结果不自动成为真实业绩。[S06]

## 1. 账户与实验隔离

`canonical` 系统标准盘：由指定策略自动管理，用户只读，用于持续前瞻评价。

`user_auto` 用户自动模拟盘：显式开启后按所选固定策略生成模拟订单；暂停只停止新自动订单，保留持仓并明确撤单范围。

`user_manual` 用户手动盘：手动模拟操作用于学习；不能归入策略准确率。初版不允许同一账户混合自动和手动，下单前切换模式会 fork 新实验，避免归因混乱。

每个 portfolio run 包含初始资金、起止、账户模式、benchmark、策略版本、执行规则、现金规则、成本配置和数据权限。默认 100,000 USD、仅做多、无杠杆、无卖空、初始整股。资金和仓位不是用户真实资产。

重置、修改初始资金或选择不同策略必须创建新 run；旧 run 归档可查，不能把亏损历史抹掉再声称连续表现优秀。用户删除账户的个人数据处理独立遵守隐私保留政策，不等于允许运营改写标准盘历史。

## 2. 第一版执行模型：NextSessionOpen-v1

正式信号在上一交易日收盘后冻结，订单必须在下一有效交易日开盘前被系统接受。参考下单数量只依赖冻结时已知 NAV、参考价格和风险预算。成交发生在下一交易日有效开盘：

```text
buy_fill_price  = raw_open * (1 + slippage_bps / 10000)
sell_fill_price = raw_open * (1 - slippage_bps / 10000)
```

默认每边 10 bps 是建模假设，包含简化价差和执行延迟影响，不代表真实券商成本；压力场景 5/10/25 bps，每边分别计算。commission 与其他 fee 为独立可配置值，初值可为 0，但界面必须写“费用假设为零”，不能写“真实交易无费用”。不得同时把同一价差重复计入两种成本。

只使用原始未复权价格成交，复权/总回报序列用于研究评价。执行引擎在开盘后拿到真实已记录的开盘行情才记账，可晚到但不得把晚生成的订单倒签至开盘。使用 EOD 行情时结果到数据到达后才显示成交，UI 明确“按开盘价模型延后确认”，不宣称实时撮合。

先卖出再买入，稳定按订单优先级和证券 ID 处理；价格跳空导致资金不足则向下裁剪整股数量，达到零则拒绝，不能透支。新买入仍须通过发行人/行业/总仓位限制；风险只裁剪规模，不据此利用未来信息改变打分。卖单超过持仓拒绝而非产生空头。

流动性限制：订单数量上限来自**截至决策时已完成的** 20 日平均成交量×0.1%，向下取整；初版不使用未来完整交易日成交量来决定开盘能成交多少。这个容量模型不能证明开盘有足够流动性，必须作为局限披露。超量部分当场取消并记录 `liquidity_cap`，不暗中顺延到最有利价格。

## 3. 时间与异常

以交易所会话 ID 而非简单日期+24h 计算可执行日。使用 UTC 保存瞬时、America/New_York 解释交易日、用户时区展示。正确处理节假日、半日市、夏令时和临时休市。

停牌、缺开盘价、证券退市或代码失效：保持 pending/risk 状态，不以前收冒充成交；初版当日计划在会话结束时失效，不自动追到后续日。需要卖出但无法成交的持仓继续保留并体现风险，不能凭“卖出建议”消除组合亏损。

晚到或更正行情：原始记录、修订记录、受影响 NAV 均有版本；对历史错误做可追溯重述，保留旧报告，不追溯改变当时的选股。盘后信息可以取消尚未开盘的订单，必须记录真实取消时间；不能改变已完成成交。

## 4. 订单状态机与幂等

`created → accepted → scheduled → filled / partially_filled / rejected / expired / cancelled`。

每个订单记录 client idempotency key、账户 run、建议版本、side、requested/accepted/filled quantity、参考价、执行会话、成本、状态原因和时间。幂等作用域是 user/portfolio/run/key；同 key 同参数返回同结果，同 key 不同参数返回 409。

撮合唯一键 `(order_id, execution_session, fill_sequence)`；同一次任务至少一次投递也只能记一次成交。数据库事务内锁定账户账本/订单，写成交、现金事件和持仓变化，再写 outbox。并发订单不能消费同一笔现金两次。

初版只有下一开盘市价模型，不承诺限价、盘中止损或盘后成交。后续实现盘中单时需新增执行版本与细粒度行情；只有 OHLC 数据不能知道高低价发生先后，同根 K 线同时触及止盈/止损必须保守处理，不能选有利顺序。

## 5. 账本与资金规则

采用 append-only 事件账本，金额/数量使用 Decimal，不用二进制浮点存钱。余额由事件归集，不允许直接 UPDATE 余额修历史。

事件类型：initial_cash、buy_cash、sell_cash、commission、fee、dividend_receivable、dividend_payment、split_adjustment、cash_in_lieu、valuation_impairment、correction/reversal。交易现金正负号固定；重放得到持仓、成本、现金、应收股息与 NAV。

初版卖出资金在模拟系统中立即计入可用买入资金，**不模拟真实券商结算、现金账户违规、税费或资金提取**；界面和报表必须明确。这一简化会影响策略可执行性，不以规则名称暗示符合真实 T+1。需要接近券商现金账户时单独实现结算日历与冻结资金模型。

NAV = cash + sum(quantity × valid_mark) + receivables。未实现盈亏和已实现盈亏分开；交易盈亏归因使用 FIFO 成本批次。无有效新价格可暂用最后有效价格并标记 stale，不能把组合当正常估值；超过预设阈值暂停排名/正式绩效发布，保留风险敞口。

## 6. 公司行动

现金股息：按官方行动的资格日规则建立 entitlement，除息时确认应收、支付日转为现金，不能只在支付日看当日持仓；特殊分红/due-bill 不支持时标记并人工核验。NAV 若已有应收就不能支付时再多加一次收益。

拆股：生效前后同步数量和单位成本，原始总成本不变；碎股作为独立应收/权益处理，现金替代需可靠行动价格。不能一面使用前复权持仓价一面再乘拆股比例。

改名/换代码：永久 security ID 不变，别名表记录生效日期。收购、换股、分拆、ADR 比例改变、退市：使用明确公司行动进行数量/现金转换；不支持自动处理时暂停该证券的正常绩效确认并进入核验，不能直接从组合删除。

退市无可变现价格时不得长期以前收当已实现财富；提供单独的估值减记情景、不可变现标记和上下界，正式报告标明不完备。历史回测也不能遗漏这类股票。

## 7. 基准与归因

至少保存：现金零收益基准（初版假设）；同试点合资格证券池的预先规定等权基准；经授权数据支持的 Nasdaq-100 ETF 总回报基准可作为额外参照，但不是全部纳斯达克指数。基准价格、分红、成本、再平衡周期、初始投入时间固定并版本化。

系统策略和基准从同一开始时点、初始资金比较；完整组合超额使用 NAV 曲线，不把所有单股票收益简单求平均。为防空仓比例不同误导，可额外报告风险/敞口匹配参照，但不能拿匹配结果替代全资金回报。

在报表中拆分：选股/择时效果、现金拖累或保护、交易成本、行业敞口、手动操作偏差、不能成交影响。不同执行模型/成本假设的策略不能混排成一个无说明榜单。

## 8. iOS 控件与操作

模拟盘首页永久显示“模拟资金”。账户概要显示 NAV、现金、持仓、应收、净/毛收益、回撤、基准、最后估值时间及异常。订单页显示排队与未成交原因；不能点击“买入”后立即假装成交。

开启自动模拟、暂停、取消待成交订单、重置实验、修改策略需要确认范围。按钮只写入本项目 paper API，不存在实盘入口。通知丢失、手机离线、用户退出 App 不影响服务器账户流程。

## 9. 验收例

100 股以 100 美元买入、每边 10 bps、零固定费用：成交价 100.10、扣款 10,010；以原始价 110 卖出：成交价 109.89、回款 10,989，净盈亏 979。样例是算术用虚构数据。

2:1 拆股前 100 股、单位成本 100；后 200 股、单位成本 50、总成本不变。原持有人应收股息在卖出后仍可支付。重复执行同订单无第二次扣款。过时行情、缺开盘价、停牌都不能产生凭空成交。各规则测试矩阵见文档 09。
